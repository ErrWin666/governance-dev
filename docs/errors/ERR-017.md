# ERR-017 — PR #4 pilot: all required checks failed on polluted diff

> Status: DIAGNOSED + FIX PUSHED — root cause was a stale PR base SHA, not the pilot code.
> Two findings were real (A8 `print(`, broken `importlinter.ini`); the rest were
> artifacts of a 65-file diff.

## What happened

PR #4 (`pilot/pgen`, first L3-lifecycle pilot: evidence/P0 + src/pgen.py +
tests/test_pgen.py) failed every required check — twice:

1. **Run 1** (runs 42689688xxx): diff was polluted — remote `main` was behind
   local, so the PR contained the whole day's work. Findings: A1 `.rego file
   has 104 lines (max 100)`; A3 `MAGICNUM [2026]` hits on doc dates.
2. **Run 2** (runs 42690704xxx): even after `main` reached `a7f4c49`, the
   checks still diffed against `pull_request.base.sha` = `6ade851` — the base
   branch head **frozen at the event time of the last push to the PR branch**.
   `git diff 6ade851...HEAD` = 65 files (day's work + 3 pilot files).

## Root cause (verified)

`pull_request.base.sha` and GitHub's PR merge-base are computed when the head
branch is pushed. `main` was pushed to `a7f4c49` *after* the `5ef9c19`
synchronize event, so every run of Run 2 still used `6ade851`. Verified:

- `gh api pulls/4` → `base.sha = 6ade851`, remote `main` tip = `a7f4c49`
- `git merge-base --is-ancestor 6ade851 a7f4c49` → true
- Local `git diff a7f4c49...5ef9c19` = exactly the 3 pilot files
- `git show --stat 5ef9c19` = empty commit; `7d444b0` = clean 3 files

**Fix mechanism: any new push to `pilot/pgen` refreshes base.sha.** No rebase
or code change was needed to un-pollute the diff.

## Fixes applied (pilot/pgen)

- `src/pgen.py`: `print(...)` → `sys.stdout.write(... + "\n")` (sys already
  imported; capsys-based tests unaffected).

  (`risky_pkg` never committed; `src/` is not a package). Both workflows
  explicitly skip lint-imports when the ini is absent. OWNER REVIEW at merge:
  removing it drops B1/D2 Python dependency-contract coverage until a real
  contract is authored.
