## Description

p5 denies any `tool_name` not in the verified inventory. The inventory
(16 names + `mcp__*` prefix) predates several tools in the current
toolset and denies them outright:

- `read_subagent` — blocked live this session (a `run_subagent`-spawned
  background agent could not be polled; only completion notifications
  work)
- `code_search`, `find_file_by_name`, `write_to_process`,
  `ask_user_question`, `request_scope`, `mcp_list_servers`,
  `mcp_read_resource` — absent, presumably denied on first use

## Root cause

Same class as ERR-005/ERR-006: the inventory is a snapshot, the toolset
grows. Fail-closed is the right default — an unrecognized name SHOULD
deny — but the discovery path (notice → owner adds name → reseal) leaves
legitimate work hard-blocked mid-task with no agent-side recourse.
