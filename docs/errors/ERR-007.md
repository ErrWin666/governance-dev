# ERR-007 — MSYS2 intermittent fork failure (cygheap read copy failed)

**Type**: Environmental flakiness / undefined gate behavior
**Discovered**: 2026-11-08 — B1.1 session, multiple exec calls
**Status**: Documented — interim mitigation applied in gate.sh

## Description

MSYS2 (Git Bash) intermittently emits
`cygheap read copy failed ... dofork: child -1 - forked process ... Resource temporarily unavailable`.
If `gate.sh` fails to fork a child process (jq, opa, timeout), the hook's behavior
is undefined — the call may be blocked or may silently pass, depending on where
the fork fails.

## Impact

- Fail-open path → silent policy bypass (worst case, M7 class).
- Fail-closed path → every tool call denied, user locked out of the session.

## Interim fix

`gate.sh` retries the OPA evaluation once after a 100 ms sleep before returning
fail_closed. Retries logged to `logs/gate.log` with marker `FORK-RETRY`.

## Final fix

Monitor `logs/gate.log` for `FORK-RETRY`/`GOV_GATE_DOWN` frequency. If fork
failures exceed **0.5%** of calls, execute Plan B (WSL migration — see STATE.md;
requires revisiting Rule 21).

Historical context: the owner experienced **chronic fork failures** in the
previous governance system (44 hooks → fork storm). The new system runs 1 hook —
it must *prove* it does not repeat the failure. Measure, do not assume.

## Regression rule

Any hook behavior change must preserve the fail-closed guarantee: fork failure
may never produce exit 0 without an OPA `allow` decision.
