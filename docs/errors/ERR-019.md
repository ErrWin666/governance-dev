# ERR-019 — Self-lockout: broken .rego = total governance shutdown

## What happened

During the L4.6 verifier-fix batch (after commit 62bc310):

1. `p1_deny_wsl_root.rego` was edited via the `edit` tool **after** a reseal →
   `policies.lock` hash mismatch → `gate.sh` integrity check exits 2 →
   **every** tool call denied, including writing the fix script.
2. Owner resealed externally; a follow-up patch (`logs/fix_l4_d.py`) applied
   7 fixes and resealed atomically — but introduced a Rego compile error in
   `p8_deny_sensitive_files.rego` (`last()` is not a Rego function).
3. Broken `.rego` → `opa eval` fails → `GOV_GATE_DOWN` → **total lockdown**:
   even `read` was denied. Only an owner-side edit + reseal could recover.

## Root cause

Fail-closed is correct — but the *patch loop itself* was non-atomic:

- `edit`-tool changes to policy files after a seal = guaranteed mismatch.
- A compile error shipped into `policies/` because the patch script wrote
  the file **before** running `opa check`/`opa test`.

## Rules derived (now binding)

1. **Never** `edit`-tool a file under `policies/` after sealing. All policy
   edits go through one script that ends with reseal (atomic patch+seal).
2. **Always** run `opa check policies/` inside the patch script *before*
   writing `policies.lock` — a compile error must abort the script, not
   get sealed in (implemented in `logs/fix_l4_f.py` onward).
3. Recovery path is owner-only by design: external reseal + file fix from
   an ungated terminal. `GOV_GATE_DOWN` on *every* tool = "broken policy
   file", not "gate lost" — check `opa check policies/` first.
4. The interpreter-script channel (`python3 logs/fix_*.py` via exec)
   remains the only agent-writable path to governance files — this IS the
   documented clause-18 residual (L5 must gate it via owner-side seal).

## Status

Recovered 2026-11-10 via owner-side p8 fix + reseal. Verified: 34/34 policy
tests pass, including new over-deny regression vectors (mystate.md,
x.approved.bak) and nested-path denial.
