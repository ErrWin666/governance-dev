# ERR-010 — fail_closed:true PROVEN (session 17)

**Type**: Governance success milestone
**Discovered**: 2026-11-08, session #17

## Description
fail_closed:true in PreToolUse hook successfully blocks tool execution when the
hook fails to run (gate.sh missing → 127 → BLOCKED, not fail-open).

## Evidence
- Test 1b (session 17): renamed gate.sh → exec 'echo test' → BLOCKED with
  "Blocked because required hook failed to run: Command exited with code 127"
- Test 2 (session 18+): kill_shell, get_output, web_search also confirmed
  blocked-then-restored
- Before fix: fail-open (session 8): hooks failed → tool executed silently

## Mechanism
Devin hook contract: non-2 exit = logged-but-not-blocking by default.
fail_closed:true overrides: non-2 exit = block. Timeout also counts as failure.

## Side effect (documented)
If hook breaks, ALL tools blocked (including read/edit → owner locked out).
Recovery = manual config edit from Windows (outside Devin).

## Mitigation
- Backup config.json.bak-failclosed exists
- Recovery procedure in STATE.md §7
- Consider separate canary hook that only logs (no fail_closed) to distinguish
  hook-down from policy-deny

## Status
Documented and proven. This is the primary local enforcement layer.
