# ERR-022 — p15 protects only 3 audit files; the PostToolUse log is forgeable

**Type**: coverage gap
**Path**: `policies/p15_deny_audit_forgery.rego:9` vs
`config.json` PostToolUse hook → `logs/b1.0-discovery.log`
**Discovered**: 2026-11-11 — session teal-income, code review
**Status**: ✅ FIXED 2026-11-10 — p15 now protects `logs/*.log` by suffix + exec_analyze.py; discovery.log covered, patch scripts stay writable

## Description

p15 denies write/edit/notebook_edit to an explicit `audit_targets` set:

```
{"logs/gate.log", "logs/b1.0-pretool.log", "policies/exec_analyze.py"}
```

The PostToolUse hook appends every tool call to
`logs/b1.0-discovery.log` — an audit artifact **not** in that set, and not
covered by p4 (outside `policies/` and `.governance/`) or p8 (no
sensitive-name match). write/edit can therefore forge or truncate the
post-tool audit trail; exec writes to it are denied by p13 (`logs/`
protected path), so the tool-name asymmetry the policy was built to close
is still open for this file. Any *new* log file has the same exposure —
the allowlist enumerates past filenames, not the `logs/` surface.

## Fix

Replace the filename set with a `logs/` prefix match (mirroring p13's
`protected_paths`), keeping `exec_analyze.py` as its own entry. If files
under `logs/` must stay agent-writable (e.g., patch scripts like
`fix_l4_d.py` live there), protect `logs/*.log` by suffix instead — that
still leaves a same-name-forgery seam; the prefix rule is the tighter one
and patch scripts can live under `tmp_probe/`/`scripts/` instead.
