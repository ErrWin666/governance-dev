# ERR-024 — Findings have a validity window in a multi-session repo

**Type**: process / assumption
**Path**: `docs/` (audit artifacts) × concurrent sessions
**Discovered**: 2026-11-11 — session teal-income
**Status**: Documented — process rule below

## Description

A verifier-subagent policy review (~11:5x) reported ~10 findings against
`policies/`. Most were **correct at review time** — but a parallel session
(`similar-plate`) had an in-flight fix batch (`logs/fix_l4_d.py`, applied
~12:41) that closed the majority: `&>>`/`>&` redirects, `find -exec`,
`xargs`, workdir pass-through, `policies.lock`-missing fail-closed, p8
basename matcher, p13 segment matching, p1 quote normalization, p15
audit-forgery.

Two bypasses confirmed live at ~12:02 (`&>>` write into `src/`,
`mv` out of `src/`) were each partially overtaken: `&>>` is dead (analyzer
now catches it — probe-verified), `mv`-source survives (→ ERR-020).

## Root cause

Not reviewer error — concurrent modification. Findings were consumed
hours after capture, against a repo whose ground truth had moved. The
verifier's line citations were accurate for its snapshot; several pointed
at code that no longer exists.

## Rule (binding for this repo)

1. Every findings document records the repo SHA / timestamp of the state
   reviewed.
2. Before a finding drives a fix or a doc, re-verify it against current
   files — a one-line probe (as done for `&>>`/`mv` here) separates live
   bugs from already-shipped fixes.
3. Uncited findings in multi-session contexts default to *unverified* —
   same standard as R5, applied across time.
