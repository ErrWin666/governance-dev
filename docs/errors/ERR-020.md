# ERR-020 — `mv` out of a protected path is not counted as a write

**Type**: bypass (residual, live-verified)
**Path**: `policies/exec_analyze.py:64-67` (+ `p13` AST layer)
**Discovered**: 2026-11-11 — session teal-income, gate-probe tests
**Status**: ✅ FIXED 2026-11-10 — mv split from cp (all non-flag args = writes) + `__main__` guard added; 34/34 tests pass

## Description

`exec_analyze.py` treats `cp` and `mv` identically: only the **last** non-flag
argument (the destination) lands in `writes`:

```
elif verb in {"cp", "mv"}:
    nf = [w for w in rest if not w.startswith("-")]
    if nf:
        writes.add(nf[-1])
```

For `cp` this is correct — the source is only read. For `mv` the source is
**unlinked** — moving a file *out of* a protected directory is a write to
that directory, and the analyzer reports `writes=[dst]` only.

## Evidence (live, this session)

1. `mv src/.gate-probe.tmp .gate-probe2.tmp` executed cleanly at ~12:02 —
   file left `src/` although `> src/x` was denied `P13-EXEC-WRITE`.
2. `mv logs/.poc-chan.txt tmp_probe/` executed at ~15:30 — same bypass.
3. Analyzer probe: `mv src/x dst` → `writes=['/mnt/c/governance-dev/dst']`
   (`no-src`). p13 layer (b) fallback never runs because `analysis_ok`,
   and `" mv "` is not in `indirection_forms` (p13:69).

## Root cause

Destination-only write semantics: the model conflates "reads a file" with
"consumes a file". A move deletes the source entry — for protected paths
that is an integrity violation even though nothing was written *into* the
path. Full chain risk: `mv src/x dst` → edit `dst` freely → content of a
protected file is modified (can't `mv` back — that direction IS denied).

## Fix

Split `mv` from `cp`: for `mv` add **all** non-flag args except option
values to `writes` (sources + destination). One line class change; add a
probe case `mv src/x dst → HITS-SRC` to `tests/policy/` or the analyzer
regression set.

## Adjacent observation

`exec_analyze.py` runs its main block at import time (no `__main__` guard)
— `import exec_analyze` reads stdin and prints `{"ok":false}` to stdout.
Harmless today (gate pipes stdin via jq) but fragile; add the guard.
