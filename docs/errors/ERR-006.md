# ERR-006 — Logged tool_name differs from function/API name (aliasing)

**Type**: Silent name-mismatch / policy-bypass-by-omission
**Discovered**: 2026-11-08 — B1.0 extension run, session 3 (`ubiquitous-headstand`)
**Status**: Documented — interim procedure applied

## Description

Tool names in hook logs differ from function/API names for two tool classes:

- MCP calls log as `mcp__<server>__<tool>` (e.g. `mcp__context7__resolve-library-id`),
  while the exposed function name is `mcp_call_tool` (which appears only as the
  `tool_use_id` prefix, e.g. `mcp_call_tool:1#...`). MCP rows also carry a
  `tool_provenance` field `{type:"mcp", server:"<name>", path:"<mcp_config.json>"}`.
- `find_file_by_name` logs as `glob` (`tool_use_id` = `find_file_by_name:N#...`).

A policy written against the function name would pass review yet never fire —
the exact silent-failure class forbidden by spec clause M7.

## Discovery method

B1.0 extension run in session 3: 13 tool names empirically captured from
`logs/b1.0-pretool.log` (PreToolUse stdin payloads), cross-checked against
`logs/b1.0-discovery.log` (PostToolUse, matching `tool_use_id`s).

## Root cause

Devin CLI normalizes tool names at hook-logging time. This normalization is not
documented in the tool API references, so the only reliable name source is the
emitted payload itself.

## Interim fix

All B1.1 policies must match against the **logged `tool_name`** (from
`b1.0-pretool.log`), never the function name. For MCP, use the `mcp__*` pattern.

## Final fix

The B1.0 procedure for any governed project must produce a verified **name
inventory** file (tool_name + observed input shapes) before any policy is
written. Inventory of record: `b1.0-pretool.log` captured names, enumerated in
`STATE.md`.

## Regression rule

A policy that references a `tool_name` absent from the last verified inventory
is invalid by construction.
