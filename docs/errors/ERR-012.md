# ERR-012 — P6/P7 are CI-based, not runtime policies — OPA cannot self-inspect

- Type: assumption
- Discovered: 2026-11-09, Phase 2 completion session
- Status: documented — implemented as CI linters

## Description
P6 (deny_policy_antipattern) and P7 (deny_secret_in_diff) were specced as
policies P6–P10 alongside the runtime .rego set (P1–P5, P8–P10). But the
runtime gate only sees tool-call JSON (tool_name + tool_input). It cannot
read its own .rego source files as policy artifacts, and it never sees a
git PR diff — both artifacts only exist in CI context.

## Root cause
Enforcement surface mismatch: the OPA gate evaluates agent tool calls;
.rego lint targets and diff contents live in pull requests, not tool calls.

## Fix / Mitigation
Implemented both as GitHub Actions workflows in ci-test (prototype):
- `.github/workflows/policy-lint.yml` — changed .rego files: ≤100 lines,
  `# WHY:` header on line 1, exactly one `package` decl, `opa check`.
- `.github/workflows/secret-scan.yml` + `.gitleaks.toml` — gitleaks over
  `base.sha..HEAD`; custom rule for `sk-[A-Za-z0-9]{20,}` (defaults miss
  alphabet-sequence tokens — discovered when first P7 test passed green).
- Verified: PR #3 (bad .rego) → lint FAIL; PR #4 (sk- secret) → scan FAIL.

## Lesson
Choose the enforcement surface by where the artifact exists:
tool call → runtime OPA; file/diff/PR → CI linter. When porting P6/P7 to a
project, copy both workflow files AND .gitleaks.toml, and confirm the check
is required in the ruleset — unrequired checks don't block merges.

## New rule
P6/P7 are replicated per-project as CI workflows, never as .rego policies.
