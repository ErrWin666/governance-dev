# ERR-014 — Empty bypass + direct push are contradictory; admin bypass accepted for dev

- Type: design trade-off / spec deviation
- Discovered: 2026-11-09, governance-dev ruleset setup (ruleset #26818941)
- Status: accepted for governance-dev only

## Description
The ruleset spec required both "required status checks" and "bypass list:
empty" while also expecting "direct push to main works". First direct push
was rejected: GH013 "2 of 2 required status checks are expected". Owner
accepted RepositoryRole:admin bypass (`bypass_mode: always`) — push then
succeeded with "Bypassed rule violations" logged.

## Root cause
GitHub's required-checks model evaluates checks attached to the pushed
commit. Checks only run on pull_request events, so a direct push arrives
with zero check results and is always rejected — the two requirements are
mutually exclusive for any non-bypassed actor.

## Fix / Mitigation
Admin bypass on governance-dev only: checks + non_fast_forward still
enforce for every non-admin actor/PR; the owner pushes directly for dev
speed. Production projects MUST use empty bypass + pull_request required
(all changes flow through PR, checks gate the merge).

## Lesson
"Empty bypass" and "direct push" cannot coexist — choose per environment.
Side effect of `bypass_mode: always`: admin can also force-push; accepted
for a solo dev repo.

## New rule
Rule 31 — production projects: empty bypass + PR required. Dev repos:
admin bypass acceptable when speed outweighs strict enforcement.
