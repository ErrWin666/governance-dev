# ERR-011 — sha256sum binary mode breaks gate.sh path parsing

**Type**: Environment / portability defect
**Discovered**: 2026-11-08, during P2 verification (test_sample.txt fixture)
**Status**: Fixed — tests.lock generated from WSL; rule recorded

## Description

`sha256sum test_sample.txt` on Git Bash (MSYS2) produces output in binary
mode by default: `e9024f... *test_sample.txt` — note the asterisk prefix.

gate.sh reads tests.lock entries via `awk '{print $NF}'` to extract the
locked path. `$NF` returns `*test_sample.txt` (with asterisk) instead of
`test_sample.txt`. The asterisk is not stripped. Result: P2's path
comparison (endswith or exact match) against the actual edited path fails →
the edit is ALLOWED instead of DENIED. A silent pass — the M7 failure class.

## Root cause

MSYS2's `sha256sum` (coreutils port) defaults to binary mode (`*` prefix),
unlike GNU coreutils on Linux which defaults to text mode (two spaces).
This is a documented portability difference in MSYS2/coreutils behavior.

## Fix / Mitigation

- **When generating tests.lock in Git Bash**: use `sha256sum -t` (text
  mode) OR generate from WSL (`wsl -e sha256sum ...`).
- **Preferred**: generate tests.lock from WSL (native Linux coreutils) —
  consistent with ADR-001 (WSL as runtime).
- **Defensive**: gate.sh's awk extraction could strip leading `*`
  (`awk '{print $NF}' | sed 's/^\*//'`) — but this is a patch, not a fix.
  Prefer correct generation.

## Lesson

A hash manifest format has platform-specific variants. The consumer
(gate.sh) must either enforce canonical format or generate manifests only
from one trusted platform.

## New rule

**Rule 29** — `tests.lock` and any hash manifest MUST be generated from WSL
(native Linux coreutils), never from Git Bash. If Git Bash is used, the
`-t` flag is mandatory and must be documented.
