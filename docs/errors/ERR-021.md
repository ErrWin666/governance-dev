# ERR-021 — Interpreter-script channel bypasses every path policy (reconfirmed)

**Type**: bypass — architectural residual
**Path**: `policies/p13_exec_write_paths.rego` (design limit) ×
`policies/exec_analyze.py` × `scripts/apply-governance-acl.ps1`
**Discovered**: known residual (ERR-019 rule 4, p13 header, "clause-18");
live re-confirmed 2026-11-11 — session teal-income
**Status**: Documented residual — owner accepted 2026-11-11
("leave documented"; fix options retained below for future phases)

## Description

The gate inspects the exec **command text**, not what the invoked program
does. `python3 tmp_probe/poc_chan.py` analyzes as `cmds=['python3']`,
`writes=[]` — p13 sees no write, indirection forms only match
`python3 -c`/`eval`/`xargs`/`find -exec`/…, so a script the agent just
wrote to any unprotected path runs arbitrary I/O on protected paths.

## Evidence (live, 2026-11-11)

- `tmp_probe/poc_chan.py` (10 lines) wrote `logs/.poc-chan.txt` —
  `logs/` is a p13 protected path; direct `> logs/f` is denied, the
  script-channel write was allowed and succeeded.
- Precedent: `logs/fix_l4_d.py` wrote `policies/gate.sh` and
  `exec_analyze.py` through this same channel (ERR-019).

## Why this matters — the backstop is thinner than assumed

`p4_governance_self_protection.rego:10` names the Windows ACL as
"layer 2". `scripts/apply-governance-acl.ps1` actually locks only:

- `policies/gate.sh`, `policies/*.rego`, `policies/.governance/`
- `%APPDATA%/devin/config.json`, `mcp_config.json`

NOT ACL-protected: `logs/` (audit forgery), `src/`, `approvals/`,
`evidence/`, `tests.lock`, `state.md` — and `policies/exec_analyze.py`
itself (the glob is `*.rego` only). So the script channel writes all of
these with no OS-level resistance. (`policies.lock` stays safe:
`.governance/` is ACL'd → analyzer tamper still ends in fail-closed
lockout, not silent bypass.)

## Root cause

Language-level command inspection cannot see process-internal I/O. The
interpreter indirection problem is unbounded (python, bash, node, perl,
powershell, awk, sqlite3, git aliases…); enumerating "dangerous verbs"
is a deny-list that never completes.

## Fix directions (owner decision required)

1. **Extend the ACL layer** to all `protected_paths` (logs/, src/,
   approvals/, evidence/, tests.lock, state.md) — moves enforcement below
   the language layer where the gate cannot be evaded. Cheapest real fix;
   needs an owner-side mechanism for legit writes (seal/restore flow
   already exists).
2. Constrain interpreter exec: deny `python3|bash|node|… <script>`
   unless the script path is under an approved allowlist (e.g.,
   `scripts/`, `tests/`) — coarse but effective in this repo.
3. Accept + audit: keep as documented residual, add PostToolUse
   snapshotting of protected-path mtimes so script-channel writes are
   *detected* even if not prevented.
