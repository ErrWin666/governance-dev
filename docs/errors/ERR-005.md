# ERR-005 — Tool-name matrix assumed from a foreign convention

**Type**: Unverified assumption / portability defect
**Discovered**: 2026-11-08 — B1.0 partial run, b1.0-discovery.log
**Status**: Documented — interim procedure applied

## Description

B1.0 assumed a 5-tool coverage matrix (`exec`, `edit`, `write`, `multi_edit`, `read`) based on Claude Code naming. Actual Devin tool names observed across 23 logged calls: `exec`, `read`, `grep`, `skill`. `multi_edit` does not exist as a Devin tool; the `edit`/`write` names are plausible but unverified.

## Discovery method

PostToolUse discovery log `logs/b1.0-discovery.log` — every row carries the real `tool_name` field emitted by the agent runtime, not an assumed name.

## Root cause

The coverage matrix was copied from a different agent's naming convention (Claude Code) without verification against Devin hook docs or observed log data.

## Interim fix

Derive tool names from the discovery log, not assumptions. Restart-note Step 1 uses observed names and treats `edit`/`write` as discovery probes rather than assumed coverage.

## Final fix

B1.0 procedure must always start with a discovery step that records real tool names before building any matcher or policy. Matchers and policies must be authored only against `tool_name` values seen in hook logs.

## Regression rule

Any matcher or policy row that names a tool absent from the discovery log is invalid by construction.
