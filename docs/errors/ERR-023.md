# ERR-023 — wsl.exe spawn fails intermittently (0xC0000142) → fail-closed stall

**Type**: environment / transport
**Path**: `%APPDATA%/devin/config.json` hooks → `wsl.exe -d Ubuntu-24.04` →
`policies/gate.sh`
**Discovered**: 2026-11-11 — session teal-income (tools blocked mid-session
with `Command exited with code -1073741502`)
**Status**: Documented — root-cause research in progress
(`docs/research/`)

## Description

The PreToolUse hook spawns a fresh `wsl.exe` per tool call (plus a second
for PostToolUse). Intermittently Windows fails to *create* the process:
exit `-1073741502` = `0xC0000142` STATUS_DLL_INIT_FAILED. `gate.sh` never
runs — `logs/gate.log` contains `PWD-PROOF` entries only for successful
spawns, with silent gaps exactly at the blocked calls. `fail_closed:true`
then converts the transport failure into a hard tool denial.

## Evidence

- Blocked calls left zero trace in `gate.log` — the failure is at Windows
  process creation, before bash/OPA/policy.
- WSL VM cold-booted at 14:58:55 (process start times + `uptime`), and
  Hyper-V `VmSwitch` is rebuilt every ~20–30 min (System log: 12:09,
  12:33, 12:48, 14:30, 14:37, 14:58) — recurring windows where `wsl.exe`
  spawn is fragile. `docker-desktop` distro also running → likely churn
  source.
- Memory pressure: ~2.7 GB free of 16 GB, ~335 processes — 0xC0000142 is
  the classic desktop-heap / resource-pressure spawn failure.
- Amplifier: 2 WSL crossings per tool call × parallel tool calls → bursts
  of 4–6 `wsl.exe`/`wslhost` spawns.

## Root cause (current assessment)

Not the policies — when `wsl.exe` spawns, the gate works correctly
(`P13-EXEC-WRITE`, `P13-EXEC-INDIRECTION` denials observed live). The
transport is a cold `wsl.exe` spawn through a VM boundary that is
periodically restarting/reconfiguring; any transient init failure hits
`fail_closed` with no retry. Exact mechanism under research.

## Interim

- Retry the blocked tool — spawn is transient, retries succeed.
- Hook wrapper that retries `wsl.exe` 2–3× with backoff would absorb the
  blips while preserving fail-closed semantics for real outages.

## Fix candidates (AWAITING OWNER — see research doc)

1. Retry wrapper around the hook command (cheap, immediate).
2. Collapse PostToolUse to Windows-native append (halves crossings).
3. Migrate the gate to Git Bash + native `opa.exe`/`jq`/python on Windows —
   removes the WSL dependency entirely (also faster: no 9P `/mnt/c` I/O).
4. Stabilize the substrate: find what rebuilds VmSwitch (Docker Desktop
   lifecycle is prime suspect), tune `.wslconfig`.
