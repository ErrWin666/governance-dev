# ERR-003 — شرط UTF-8 غطّى الملفات فقط، لا stdin/stdout

**النوع**: ثغرة تنفيذ + فجوة مواصفة
**تاريخ الاكتشاف**: 2026-11-09
**المكتشف**: T1 في P3 للمشروع التجريبي — أثناء التشغيل اليدوي الحي
**الحالة**: مُصلح في الكود + بانتظار تعديل المواصفة (M3)

## الوصف

`spec.md` يشترط `encoding='utf-8'` لعمليات قراءة/كتابة `notes.json` فقط. على Windows (cp1252)، النص العربي عبر stdin يُقرأ مُشوَّهاً قبل وصوله للملف (mojibake `Ø§Ù„Ø³Ø·Ø±`)، ورسائل العربية المطبوعة تنهار بـ`UnicodeEncodeError` — كلا الفشلين ظهرا حياً في T1.

## السبب الجذري

"الافتراض الصامت هو الثغرة" — نفس جذر `\\?` القديم: المنصة الافتراضية (cp1252 على Windows Python) لا تُذكر، فتبقى ثغرة غير مرئية حتى التشغيل الحقيقي.

## الإصلاح المطبق (في الكود)

`sys.stdin.reconfigure(encoding="utf-8")` + `stdout`/`stderr` — 3 أسطر في `main()`.

## الإصلاح المطلوب في المواصفة (مقترح، بانتظار M8/M3)

- §4: معيار قبول "النص المُدخل عبر stdin يُقرأ بترميز UTF-8 صراحةً".
- §8: "جميع I/O (files + stdin/stdout/stderr) تستخدم `encoding='utf-8'` صراحةً".

## اختبار الانحدار

T4 يجب أن يتضمن اختباراً بإدخال عربي متعدد الأسطر عبر stdin حقيقي — لا نص إنجليزي يخفي cp1252.
