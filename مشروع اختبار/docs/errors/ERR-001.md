# ERR-001 — آلية التوقيع غير معرّفة في M8

**النوع**: فجوة مواصفة (spec gap)
**تاريخ الاكتشاف**: 2026-11-09
**المكتشف**: المشروع التجريبي — بوابة P0
**الحالة**: مفتوح — حل مؤقت مطبق

## الوصف

المواصفة (§P0 معايير القبول، وM8) تطلب "مواصفة موقعة" و"موافقة صريحة مسجلة" دون تعريف ما يعنيه "التوقيع" تقنياً: هل هو سطر نصي؟ موافقة في المحادثة؟ hash موقّع؟ لا آلية محددة.

## السبب الجذري

المواصفة كُتبت بمستوى مفاهيمي ("المالك يوافق") دون تحديد السطح الميكانيكي للموافقة — نفس نمط "الفعل لا النية" لكن على آلية ثقة المالك نفسها.

## الحل المؤقت المطبق

موافقة المالك النصية تُسجّل في `approvals/approval.md` مع التاريخ والمرحلة المُعتمَدة. ليست توقيعاً تشفيرياً — لكنها أثر ملموس مسجل.

## الحل النهائي (مقترح — لاحقاً)

توقيع cosign أو hash ملف الموافقة — يُقيَّم بعد اكتمال دروس المشروع التجريبي.

## اختبار الانحدار

عند تعديل المواصفة: كل آلية إلزامية يجب أن تسمّي سطحها الميكانيكي صراحةً (من ينفذها، بأي أداة، أين تُسجل النتيجة).
