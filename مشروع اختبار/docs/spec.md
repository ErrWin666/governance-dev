# spec.md — نظام الملاحظات CLI (مشروع اختبار)

**الإصدار**: 1.0
**الحالة**: بانتظار موافقة المالك (M8)
**المرحلة**: P0 — الاستكشاف
**تصنيف المشروع**: صغير — يجوز تخطي P1 وP2 والانتقال من P0 إلى P3 مباشرةً، بشرط إعفاء موثق من المالك في `approvals/approval.md`. التخطي لا يعفي من بقية الآليات (عقود المراحل، الأدلة، الاختبارات، حدود الحجم).

---

## 1. المشكلة

المالك يحتاج تسجيل ملاحظات نصية سريعة من سطر الأوامر دون فتح محرر أو تطبيق. الملاحظات قد تكون فقرات متعددة الأسطر، ويجب استرجاعها والبحث فيها بسهولة. الحلول الجاهزة (تطبيقات ملاحظات) أثقل من الحاجة وتتطلب فتح واجهات.

## 2. المستخدم

المالك نفسه — مستخدم واحد، غير تقني، على Windows + WSL2 (Ubuntu 24.04).

## 3. الوظائف المطلوبة

| # | الوظيفة | الوصف |
|---|---|---|
| F1 | `note add` | إضافة ملاحظة نصية تسمح بأسطر متعددة (فقرة أو أكثر). يقرأ النص من stdin ويسمح بأسطر متعددة حتى Ctrl+D (EOF) |
| F2 | `note list` | عرض كل الملاحظات مع ترقيمها. كل ملاحظة في سطرين: `[id] created` ثم نص الملاحظة كاملاً بدون اقتطاع |
| F3 | `note search <كلمات>` | بحث نصي يعيد الملاحظات التي تحتوي **كل** الكلمات المعطاة (AND)، بغض النظر عن حالة الأحرف |

## 4. معايير القبول (قابلة للاختبار)

- [ ] `note add` يحفظ ملاحظة متعددة الأسطر دون فقدان أي سطر.
- [ ] `note list` يعرض كل الملاحظات مرقمة بتنسيق مقروء.
- [ ] `note search "كلمة"` يعرض فقط الملاحظات المحتوية على الكلمة.
- [ ] البحث يرجع نتيجة فارغة واضحة (لا صمت) عند عدم وجود تطابق.
- [ ] البيانات تُحفظ في `notes.json` بصيغة JSON مقروءة بشرياً (indent، ليس سطراً واحداً مضغوطاً).
- [ ] `notes.json` يُنشأ ويُقرأ من مجلد السكربت دائماً، لا من cwd.
- [ ] أول تشغيل على ملف غير موجود لا يفشل (ينشئ بنية فارغة).
- [ ] إدخال ملاحظة فارغة ممنوع برسالة واضحة.
- [ ] إذا كان `notes.json` موجوداً لكنه JSON غير صالح، يطبع السكربت رسالة خطأ واضحة ويخرج بكود خطأ غير صفري، ولا يحذف الملف تلقائياً.
- [ ] النص العربي (بما فيه الأسطر المتعددة) يُحفظ ويُعرض عبر add/list/search دون تشويه — لا يظهر كـ(Ø§Ù„Ø³Ø·Ø±).

## 5. خارج النطاق (صراحةً)

- ❌ وسوم / تصنيفات / فئات (إصدار 2 محتمل)
- ❌ تعديل ملاحظة موجودة
- ❌ حذف ملاحظة
- ❌ تنسيق Markdown أو قوائم أو عناوين
- ❌ تصدير / استيراد
- ❌ مزامنة سحابية / قاعدة بيانات / شبكة
- ❌ واجهة رسومية أو ويب
- ❌ تشفير أو حماية المحتوى

## 6. البدائل المدروسة

| البديل | لماذا رُفض |
|---|---|
| ملف نصي `notes.txt` سطري | يفشل مع ملاحظات متعددة الأسطر — يحتاج فواصل هشة |
| SQLite | أثقل من الحاجة — مستخدم واحد، JSON يكفي ويقرأ بشرياً |
| تطبيق جاهز (Obsidian/Notion) | لا يعمل من سطر الأوامر، تعقيد وإعداد زائد |

## 7. الأسئلة المفتوحة

| # | السؤال | الحالة |
|---|---|---|
| Q1 | مسار `notes.json` الافتراضي = مجلد السكربت أم مجلد العمل؟ | ✅ **مُجاب: بجانب السكربت دائماً، لا cwd** |
| Q2 | لغة الواجهة — الأوامر والرسائل؟ | ✅ **مُجاب: أوامر إنجليزية + رسائل عربية** |

## 8. التقنية

- لغة واحدة: Python 3.12 (مثبت في WSL).
- تخزين: `notes.json` — بنية `[{"id": int, "created": "ISO", "text": "..."}]`.
- `id` = (max(id) + 1) من الملاحظات الموجودة، أو 1 إذا كانت القائمة فارغة.
- `created` بتنسيق ISO 8601: `YYYY-MM-DDTHH:MM:SS` (بدون timezone).
- جميع عمليات I/O (ملفات + stdin/stdout/stderr) تستخدم `encoding='utf-8'` صراحةً.
- لا مكتبات خارجية (stdlib فقط: `json`, `sys`, `datetime`, `pathlib`).
